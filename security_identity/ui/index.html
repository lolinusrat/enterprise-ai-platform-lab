Why the denial does not depend on the agent's instructions

The model only proposesIt returns tool-call JSON. The runtime executes it, through the gateway, and nothing else can reach the records store.
Identity comes from the sessionUser, agent id and session id are attached by the runtime. A prompt cannot change who the request is for.
OPA checks the grant itselfSignature against the authorization server's JWKS, expiry, audience, user, session, agent and customer. A made-up or borrowed grant fails.
Entitlement is re-checkedEach read re-runs the grant policy, so a grant cannot be pointed at another customer or outlive the relationship it was issued for.
Fields come from policyThe purpose in the signed grant decides which fields leave the gateway. The agent cannot ask for more.
Fails closedIf OPA is unreachable or returns no decision, the gateway denies.
