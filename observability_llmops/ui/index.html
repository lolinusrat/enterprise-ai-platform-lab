Architecture

Three layers: the agent at runtime, the telemetry pipeline that observes it, and the evaluation loop that reads the telemetry to gate changes.

One request, step by step

What runs, and which span each step emits.

  1. Root span. graph.invoke() fires on_chain_start with no parent, which opens invoke_agent support_agent. The span starts a new trace.
  2. classify node. This opens node classify, and the LLM call inside it opens chat openai/gpt-oss-20b. The chat span records gen_ai.usage.input_tokens, output_tokens, reasoning_tokens and cost_usd from the response's usage_metadata.
  3. Route. The router function produces no span; its callback events are attached to the nearest traced ancestor. An intent of other goes to decline, which makes no model call and costs nothing.
  4. agent ⇄ tools loop. Each agent turn opens node agent with a chat span inside it, and the chat span lists the tool calls it requested. Each tool call opens execute_tool lookup_order (or the other tools) under node tools.
  5. End. The root span gets support.intent and closes. The collector hands the whole trace back to the caller, and usage.summarize() adds up tokens, cost and the tool trajectory from the spans alone.
  6. Eval. The runner scores the answer and the tool trajectory against the case, then compare() checks the run against the baseline and its thresholds.

Message content isn't recorded unless OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true (currently off). OTLP export: off.
